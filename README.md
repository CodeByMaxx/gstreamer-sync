# GStreamer Sync Overlay

This project demonstrates a video pipeline with synchronized bounding box
overlays using GStreamer.

A dummy camera generates video frames which are pushed into a GStreamer
pipeline using `appsrc`. Detection results are generated independently and
synchronized with the video stream using timestamps. The overlay is rendered
using GStreamer's `cairooverlay` element.

---

# Architecture

```
DummyCamera
     |
     | RGB Frames + PTS
     v
 VideoSource
     |
     | appsrc
     v
 videoconvert
     |
     v
 cairooverlay
     |
     v
 videoconvert
     |
     v
 autovideosink


Detection Thread
     |
     | Detection + Timestamp
     v
 Overlay
```

# Components

## DummyCamera

`DummyCamera` simulates a camera source without requiring real camera
hardware.

Features:

- Resolution: 640x480
- Pixel format: RGB
- Frame rate: 30 FPS
- Generates timestamps for every frame

The generated frames are passed directly to:

```
VideoSource::pushFrame()
```

---

## VideoSource

`VideoSource` encapsulates the GStreamer pipeline.

Responsibilities:

- Creates the GStreamer pipeline
- Creates and connects pipeline elements
- Manages the `appsrc` element
- Pushes video buffers into GStreamer
- Preserves frame timestamps (PTS)


Example pipeline:

```
appsrc
  |
videoconvert
  |
cairooverlay
  |
videoconvert
  |
autovideosink
```

---

## Overlay

The overlay implementation uses GStreamer's `cairooverlay` element.

Responsibilities:

- Stores incoming detection results
- Matches detections with video frames using timestamps
- Draws bounding boxes on the video stream


The synchronization is based on the Presentation Timestamp (PTS).

Example:

```
Video Frame:

PTS = 1500 ms


Detection:

PTS = 1501 ms


Difference:

1 ms


Result:

Detection is applied to the frame
```

---

# Timestamp Synchronization

The video pipeline and detection processing run in separate threads.

Each video frame receives a timestamp:

```
Frame:

1000 ms


Detection:

1020 ms


Time difference:

20 ms
```

During rendering, the overlay searches for the detection result with the
smallest timestamp difference.

This simulates a real computer vision pipeline where inference results arrive
slightly delayed compared to the camera frames.

# Requirements

Required software:

- C++17
- CMake >= 3.16
- GStreamer 1.0
- Cairo
- GoogleTest


Ubuntu installation:

```bash
sudo apt install \
    cmake \
    build-essential \
    libgstreamer1.0-dev \
    libgstreamer-plugins-base1.0-dev \
    libcairo2-dev \
    libgtest-dev
```

---

# Build

Create a build directory:

```bash
mkdir build
cd build
```

Configure the project:

```bash
cmake ..
```

Build:

```bash
make -j8
```

---

# Run

After a successful build:

```bash
./overlay
```

A video window will open showing the generated video stream.

Bounding boxes are generated by the detection thread and displayed when a
matching timestamp is found.

---

# Unit Tests

Build the tests:

```bash
make
```

Run tests:

```bash
ctest --verbose
```

Current tests:

## FindsClosestDetectionByTimestamp

Checks that the detection with the smallest timestamp difference is selected.

---

## ReturnsNothingWhenTimestampTooFarAway

Checks that detections outside the allowed synchronization window are ignored.

---

## ChoosesSmallestDifference

Checks that the closest detection is selected when multiple candidates exist.

# Future Extensions

The current `DummyCamera` replaces a real camera source and is used to test
the complete synchronization pipeline.

Possible future extensions:

- Replace `DummyCamera` with a real camera source
- Connect an object detection model
- Add tracking between frames
- Support different video formats
- Add hardware accelerated video processing

---

# Goal

The goal of this project is to provide a simple and extensible foundation for
a synchronized video processing pipeline where camera frames and AI detection
results are combined in real time.
